# GridKit Setup Guide

## MacPorts Setup

Download and install MacPorts from [macports.org](https://www.macports.org). MacPorts manages and installs compilers and development tools from the command line.

Update to the newest version and get the latest LLVM 18 package:

```bash
sudo port selfupdate
```

Install the required tools:

```bash
sudo port install cmake      # generates build instructions and tells the compiler what files to compile and how to link them together
sudo port install ninja      # fast build tool that executes the compilation steps generated by CMake
sudo port install git        # downloads and manages source code repositories from sites like GitHub

sudo port install python314
sudo port select --set python python314
sudo port select --set python3 python314
```

Check which shell you're on:

```bash
echo $SHELL
# /bin/zsh   → use ~/.zprofile
# /bin/bash  → use ~/.bash_profile
```

When you install something with MacPorts, it updates your PATH in your shell config file. Those changes need to be reloaded manually:

```bash
source ~/.zprofile      # zsh
source ~/.bash_profile  # bash
```

When to reload:
- After `sudo port select --set python python314` — so your terminal finds the new Python when you type `python`
- After `sudo port select --set clang mp-clang-18` — so `clang --version` reflects Clang 18, not Apple's default

## Dependency Build Order

Each dependency depends on the previous — build order matters:

1. MacPorts tools (`cmake`, `ninja`, `git`, `python314`)
2. LLVM 18 + Clang 18 (compiler for everything below)
3. SuiteSparse/KLU (math library for SUNDIALS)
4. SUNDIALS (Ordinary Differential Eq/Differential Algebraic Eq solver, requires KLU)
5. Enzyme AD ( Automatic Differentiation, requires LLVM 18)
6. GridKit (requires SUNDIALS + Enzyme)

## Libraries

### SuiteSparse (KLU)

Provides `SuiteSparse_KLU` for sparse linear solvers used in SUNDIALS.

### LLVM 18 + Clang 18

```
LLVM 18
├── Clang 18       ← C/C++ compiler
├── LLVM libraries
└── Optimizers     ← transform LLVM IR to make code faster without changing behavior
```

`llvm-18` and `clang-18` are the specific versions required by GridKit and Enzyme. Apple's built-in Clang is a modified fork that lags behind upstream LLVM.

```bash
sudo port install llvm-18
sudo port install clang-18
sudo port select --set clang mp-clang-18
```

> **CMake** tells the compiler what files to compile and how to put everything together.

## SUNDIALS

SUNDIALS is the first layer for GridKit. Every component follows the same `source/build/install` directory pattern:

```
sundials/
├── sundials/    ← source
├── build/       ← compiler output
└── install/     ← built through build directory, compiles to install afterwards
```

### Clone SUNDIALS

```bash
cd ~/Desktop/ORNLproject/src/sundials
git clone https://github.com/LLNL/sundials.git
```

### Configure and Build

> ⚠️ `SUNDIALS_ENABLE_KLU=ON` must be set explicitly. CMake will silently accept an unknown variable, log it as `UNINITIALIZED`, and build SUNDIALS without KLU support.

If KLU is missing, verify with:

```bash
cat ~/Desktop/ORNLproject/src/sundials/build/CMakeCache.txt | grep -i klu
sudo port install SuiteSparse_KLU
```

Run CMake with the following flags:

```bash
cmake ~/Desktop/ORNLproject/src/sundials/sundials \
  -DCMAKE_INSTALL_PREFIX=~/Desktop/ORNLproject/src/sundials/install \
  -DCMAKE_C_COMPILER=/opt/local/libexec/llvm-18/bin/clang \
  -DCMAKE_CXX_COMPILER=/opt/local/libexec/llvm-18/bin/clang++ \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DSUNDIALS_ENABLE_KLU=ON \
  -DKLU_INCLUDE_DIR=/opt/local/include \
  -DKLU_LIBRARY_DIR=/opt/local/lib

make -j$(sysctl -n hw.logicalcpu)
make install
```

> ⚠️ A stale `CMakeCache.txt` preserves old broken values even when you pass correct flags. If reconfiguring after a failure:
> ```bash
> cd ~/Desktop/ORNLproject/src/sundials/build
> rm -rf *
> ```

## Enzyme AD

Enzyme is an automatic differentiation (AD) plugin for LLVM. It automatically generates code that computes derivatives (gradients, sensitivities, Jacobians, etc.).

### Clone Enzyme

```bash
cd ~/Desktop/ORNLproject/src/enzymeAD
git clone https://github.com/EnzymeAD/Enzyme
```

Repository structure:

```
Enzyme/           ← repo root, contains top-level CMakeLists.txt
└── enzyme/       ← actual Enzyme plugin source with its own CMakeLists.txt
```

> ⚠️ If you run `cmake` from the repo root (`Enzyme/`) pointing at `../llvm`, CMake will error saying the LLVM source directory does not exist. Always `cd` into `enzyme/` first.

### Build Enzyme

```bash
cd ~/Desktop/ORNLproject/src/enzymeAD/Enzyme/enzyme
mkdir build && cd build

cmake .. \
  -G Ninja \
  -DCMAKE_C_COMPILER=/opt/local/libexec/llvm-18/bin/clang \
  -DCMAKE_CXX_COMPILER=/opt/local/libexec/llvm-18/bin/clang++ \
  -DLLVM_DIR=/opt/local/libexec/llvm-18/lib/cmake/llvm \
  -DCMAKE_CXX_FLAGS="-stdlib=libc++" \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX=~/Desktop/ORNLproject/src/enzymeAD/install

ninja
ninja install
```

> **Ninja vs Make:** Ninja is faster and better at parallel builds. It executes the build instructions generated by CMake, finds files that need compiling, calls Clang 18 on those files, and links everything together into the Enzyme library.

### Verify Installation

```bash
find ~/Desktop/ORNLproject/src/enzymeAD/install -name '*Enzyme-18.dylib'
```

Expected output:
✓ ./lib/LLVMEnzyme-18.dylib
✓ ./lib/LLDEnzyme-18.dylib
✓ ./lib/ClangEnzyme-18.dylib

## GridKit

GridKit provides a modeling framework for power systems simulations and analysis, supporting dynamic constrained optimization and partitioned numerical integrators for systems of differential and algebraic equations.

### Step 1: Clone GridKit and Submodules

```bash
cd ~/Desktop/ORNLproject/src/ornl_gridkit
git clone https://github.com/ORNL/GridKit.git
cd GridKit
git submodule update --init third-party/
```

> ⚠️ GridKit's build directory must be a **sibling** of the source directory, not inside it:
> ```
> ✓ ornl_gridkit/build/      (sibling of GridKit/)
> ✗ ornl_gridkit/GridKit/build/  (inside source)
> ```

```bash
cd ~/Desktop/ORNLproject/src/ornl_gridkit
mkdir build && cd build
```

### Step 2: CMake Configuration

```bash
cmake ../GridKit \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCMAKE_C_COMPILER=/opt/local/libexec/llvm-18/bin/clang \
  -DCMAKE_CXX_COMPILER=/opt/local/libexec/llvm-18/bin/clang++ \
  -DSUNDIALS_DIR=~/Desktop/ORNLproject/src/sundials/install \
  -DEnzyme_DIR=~/Desktop/ORNLproject/src/enzymeAD/install/lib/cmake/Enzyme \
  -DENZYME_LLVM_PLUGIN_LIBRARY=~/Desktop/ORNLproject/src/enzymeAD/install/lib/LLVMEnzyme-18.dylib \
  -DENZYME_CLANG_PLUGIN_LIBRARY=~/Desktop/ORNLproject/src/enzymeAD/install/lib/ClangEnzyme-18.dylib \
  -DCMAKE_INSTALL_PREFIX=~/Desktop/ORNLproject/src/ornl_gridkit/install \
  -DCMAKE_OSX_SYSROOT="$(xcrun --sdk macosx --show-sdk-path)" \
  -DCMAKE_EXE_LINKER_FLAGS="-Wl,-rpath,/opt/local/lib" \
  -DCMAKE_SHARED_LINKER_FLAGS="-Wl,-rpath,/opt/local/lib" \
  -DGridKit_ENABLE_SUNDIALS=ON \
  -DGridKit_ENABLE_ENZYME=ON
```

### Step 3: Build and Install

```bash
cmake --build . -j$(sysctl -n hw.logicalcpu)
cmake --install .
```
- `cmake --build` runs make under the hood with parallel jobs
- `cmake --install` copies libraries and headers to the `install/` prefix
- Build type must be `RelWithDebInfo` or `Release` when Enzyme is enabled 

### Step 4: Verify

```bash
cd ~/Desktop/ORNLproject/src/ornl_gridkit/build
ctest --output-on-failure
```

With SUNDIALS and Enzyme both enabled, nearly all tests should pass.

### Step 5: Test Results

✓ 65/66 tests passed in "n" seconds
✗ Test #44: EnzymePowerElectronicsCheck — floating point epsilon mismatch

The autodiff Jacobian computed `2.06027e-14` where the reference expects `0`. This is effectively machine epsilon on ARM — the values are numerically identical. This is a known tolerance issue on Apple Silicon and does **not** affect GridKit functionality.

## Compiler Notes

### Why LLVM/Clang 18 Exclusively

This project uses **LLVM/Clang 18** exclusively — not Apple Clang, not GCC.

- Apple's built-in Clang is a modified fork that lags behind upstream LLVM
- GCC is not used because Enzyme AD is an LLVM plugin and requires Clang
- All three components (SUNDIALS, Enzyme, GridKit) must use the **same compiler** — mixing compilers causes ABI mismatches, linking errors, and incompatible libraries

### Set Active Clang

```bash
sudo port select --set clang mp-clang-18
```

### Verify Active Clang

```bash
clang --version
```

> ⚠️ Always `rm -rf *` the build directory before reconfiguring after any failure.
